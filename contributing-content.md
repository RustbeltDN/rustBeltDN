# Adding & Updating Content on the Rustbelt Digital Network Website

Welcome, new member! This page walks you through adding yourself to our website,
updating your existing profile, and sharing events with the network. Very little
technical experience is required, but you will need a GitHub account and a few minutes!

## 0. Request access (first time only)

Before you can save any changes, we need to add your GitHub username to
the repository! This is a one-time step. GitHub authentication
and authorized membership in our GitHub repository serve as controls on 
who can contribute content, so we'll have approve you for membership, and then
you can post. 

Don't have a GitHub account yet? They're free! Sign up at
[github.com/join](https://github.com/join).

Once you have an account, send your GitHub username to
[Elisa Beshero-Bondar](mailto:ebbondar@gmail.com) with subject line: "Rustbelt DN membership" (and say hi!) and we'll add you to our GitHub organization and Rustbelt DN repository.

After that, when you're authorized as a member, you're all set to
log in and manage your own profile and post updates anytime. There's no need to ask us again for
future updates.

## 1. Log in

After you're through step 0 and cleared to contribute, 
go to **[rustbeltdn.github.io/rustBeltDN/admin/](https://rustbeltdn.github.io/rustBeltDN/admin/)**
and click **Login**. You'll be asked to sign in with GitHub.

Once you're in, you'll see two sections: 
* **Who We Are** (member
profiles)
*  **Events**. 
Use whichever guide below matches what you're
adding. You can always come back and do the other later.

## Adding or Updating Your Profile

### Find your entry, or start a new one

- **Already have a profile?** Look for your name in the list and click
  it to open it for editing.
- **Adding yourself for the first time?** Click the button to create a
  new entry (it may say "New" or show a **+**).

If you're not sure whether you already have an entry, it's worth
checking the list first — editing your existing one keeps everything in
one place, rather than creating a duplicate.

### Fill in your profile

| Field | What to put |
|---|---|
| **Full Name** | Your full name as you'd like it displayed on the "Who" page. |
| **Last Name (for alphabetizing)** | Just your last name, or whatever name you'd like the directory sorted by. This isn't shown on the page — it only controls where you appear in the alphabetical listing. |
| **Pronouns** | Optional. |
| **Role** | Optional: a short title or description, like "Founding member" or "Alum, Class of 2019." |
| **Photo** | Optional. See the note on image descriptions below if you add one. |
| **Bio** | Tell us about yourself! A few sentences is plenty. See formatting tips below. |

### Adding your projects (optional)

If you'd like to share projects you're working on, scroll to the
**Projects** section and add one entry per project:

- **Project Title** : the name of the project.
- **Project Image** : optional. If you add an image here, you'll also
  be asked for a short description of it (see below) — the two go
  together, so either fill in both or leave both blank.
- **Project Link** : optional. Where should people go to learn more?
- **Description** : optional. A sentence or two about the project;
  supports the same formatting as your bio.

You can add as many project entries as you like.

## Adding an Event

### Find the event, or start a new one

Same idea as with profiles: check the **Events** list first in case
someone's already started the entry you have in mind, or click the
button to create a new one (it may say "New" or show a **+**).

### Fill in the event

| Field | What to put |
|---|---|
| **Event Title (What)** | A short, clear name for the event. |
| **Hosted By (Who)** | Your name, or the name of the group hosting. |
| **Date (When)** | The date of the event. |
| **Location (Where)** | An address, building name, or "online" (with a link in the description below). |
| **Event Image** | Optional. See the note on image descriptions below if you add one. |
| **Description** | Optional: any extra details people should know. Supports the same formatting as a bio (see below). |

Worth knowing: you don't need to do anything to move an
event to "Past Events" once it's happened! We have a script configured on our website 
to handle that automatically based on the date you enter and its comparison to today's current date!

## Note on image descriptions

Whenever you add an image (your profile photo, a project image, or an
event image), you'll see a field for a short text description. This is
what's called "alt text" — it lets people using screen readers (a
common accessibility tool for people who are blind or have low vision)
understand what's in the picture, since they can't see it directly.

A good description is brief and specific:

> Good: "Photo of Jane smiling on a hiking trail, mountains in the
> background."
>
> Not as helpful: "Photo" or "IMG_2043."

For a project logo, screenshot, or event flyer, just describe what it
looks like — you don't need to explain what it's *for*, since that's
what the description field is for.

## Formatting your text

Bios, project descriptions, and event descriptions all support a few
simple markdown formatting shortcuts:

- **Bold text**: wrap words in two asterisks — `**like this**` becomes
  **like this**.
- **Links**: `[link text](https://example.com)` becomes a clickable
  link reading "link text."

(And you don't need to use any formatting at all. Plain sentences work
perfectly fine too.)

## Save your changes

When you're done, use the button to save/publish your entry. Your
submission goes through a quick review (via a Pull Request) before it appears on the live
site. This is normal for everyone, as we need to review submissions before they post, and not a sign anything went wrong, so don't worry if you don't see your changes immediately. One of us who is
monitoring our GitHub repo will typically review on the same day or in a day or two if we're busy.

(About that: if you're familiar with GitHub repositories, once you're a member you can help us review pull requests to update the site! Just skim through them, merge to main, and delete the branch if the content looks fine. We'll appreciate the help! Also, if you know what you're doing, it's okay to to merge your own Pull Requests, though it's best practice to get someone else to merge them.)
